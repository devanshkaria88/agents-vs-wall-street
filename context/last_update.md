## 1. Adaptive/self-learning — yes, but the honest version

True self-learning (train on outcomes, improve) doesn't fit a one-shot forecast: the ground truth arrives on 20 Aug, after we're locked. But there are three real adaptive loops available today, in increasing time-horizon:

**Backtest-driven calibration (the one worth building this afternoon).** The corpus has 8+ quarters of history per company, including what each company *guided* and what it then *reported*. So the engine's parameters don't have to be hand-picked: we replay history — "forecast Q3 FY25 using only documents dated before it" — score ourselves against the actual (which is in the corpus), and *fit* the adjustment parameters from that: ADI's +2.2–2.8% beat bias, Deere's Q3-share-of-H2 ratio, whether "top of range" historically means the number or £0.5m above it. The system tunes itself on held-out history, deterministically and reproducibly. That's genuine learning-from-data, it's cheap (the dossiers already contain the guide-vs-actual pairs), and it's the strongest possible answer to the judges' "how does the system reason its way to a forecast" question.

**Runtime self-correction.** The validator doesn't just reject bad values — rejection feeds back to the extractor ("your net-fees driver failed the range check; find corroborating evidence or return to anchor"), with bounded retries and both attempts logged. Self-correcting, not self-learning, but it's the adaptive behavior judges can actually watch in the run log.

**Cross-event learning (the story, and real).** The knowledge layer the agent wrote this morning *is* its memory. OpenStocks runs ongoing $100 prizes per earnings event after today — when the four actuals land, the agent scores itself and rewrites its own skills (which anchors worked, which bias estimates were off). "The agent authored its own memory, then updates it from measured outcomes" is a true sentence we can put in front of judges, with the first half already in the git history.

## 2. What the AI actually does at runtime

The LLM is not "predicting" — the engine predicts. The LLM's runtime job is **agentic evidence-gathering over 1,139 documents**, and the intelligence shows up in four places:

- **Exploration:** it gets tools (`search_corpus` — ripgrep, `read_doc`) and a target metric, not a reading list. It decides what to search, follows cross-references ("as guided at our June trading update" → go find the June update), and works the company INDEX like an analyst would. The dossier skills make it fast, but it must re-verify and may override with newer evidence.
- **Interpretation:** the genuinely hard part machines-without-language fail at — knowing that a footnote about six divested countries changes the net-fees basis, that ADI guides *operating* margin but we're scored on *gross* margin, that "£4 3.5 m" in OCR-mangled text is £43.5m.
- **Proposing the calculation plan:** for each metric it emits *which* anchor, *which* adjustments, *what* formula — as structured JSON with a citation per input. The deterministic engine executes the plan; reasoning chooses the math, code performs it.
- **Reacting:** validator rejections come back to it with the reason, and it re-searches.

And a hard boundary makes all of that trustworthy: every quoted line is re-checked by code as an exact substring of the cited file. The extraction agent literally cannot invent evidence. (This ran once already today — my research subagents scored 144/144 through that same firewall.)

## 3. LoRAs — no, and here's the honest reasoning

A LoRA is a cheap fine-tune of an open-weight model. For today it fails on all three axes: **data** (you'd need thousands of labeled extraction pairs or forecast outcomes; we have 12 targets and ~30 historical quarters — a numeric fine-tune on that overfits instantly), **time** (hours of setup for negative expected payoff vs. prompting + deterministic code), and **model access** (the frontier model doing our reading can't be LoRA-tuned by us; we'd have to swap to a small open model and *downgrade* the one component where model quality matters). Whoever you overheard was probably imagining a fine-tuned financial-metric extractor — which is a real thing at scale (thousands of companies, cost pressure), just not a thing that helps four companies in six hours under a scoring rule that rewards not-blowing-up. It goes in the architecture HTML's "considered and rejected" section — which, genuinely, earns points: Honesty & self-knowledge is a scored category, and "we evaluated fine-tuning and can articulate exactly why it loses here" is a much better judge answer than a LoRA bolted on for optics.
