Agents vs Wall Street · 16 Aug 2026

The Truth

An agent that reads 1,139 company documents, quotes its evidence byte-for-byte, lets deterministic code do every calculation, and refuses to be a hero anywhere it lacks receipts.

Agent name: The Truth · Team: Devansh Karia (solo)

Build style: hybrid — built interactively in Claude Code (claude-fable-5); the runtime is a standalone Python agent on the Anthropic API (claude-opus-5) + deterministic Python.

Final command: npm run forecast · Repository: github.com/devanshkaria88/agents-vs-wall-street

What it does, in one paragraph

Four companies report earnings in the next four days. The Truth forecasts the twelve scored metrics by exploiting one observation: the companies have already told us most of the answers. Hays stated on 10 July that FY26 operating profit lands "at the top of the £37.0–46.0m consensus range". ADI guided Q3 revenue to $3.9B — and has beaten its own midpoint eight quarters straight by a measurable ~+$75M median. Home Depot's quarter contains a full quarter of the GMS acquisition (~$2.0B) that the year-ago quarter lacks. The agent's job is to find those statements, quote them exactly, and hand them to code that applies the companies' own arithmetic to their own words.

The deliverable: twelve yellow spreadsheet cells. Everything below exists to put defensible numbers in them.

Three rules the whole design hangs on

  1. The AI never does arithmetic; the code never guesses. The LLM extracts facts with citations; pure Python applies growth rates, divides profits by share counts, blends paths. Same inputs → same twelve numbers, every run.
  2. Every quote is re-verified byte-exact. A citation firewall re-finds each quoted line as an exact substring of the cited file. The agent cannot invent evidence — a quote that doesn't re-find kills the driver. (Bootstrap research scored 144/144 through this same firewall; it caught two formatting drifts.)
  3. Never a blank cell. A missing metric scores an automatic 5.0 — the worst possible. Guidance-anchored baselines went green at 11:24; every later stage only overwrites the workbooks after validation passes.

The pipeline (this is the real dataflow of npm run forecast)

Corpus

1,139 frozen markdown documents (filings, transcripts, slides) — plus a logged, reviewed public-web consensus sweep done at 12:30

↓ raw filings & transcripts
Reader — our own agent (agent/loop.py)

Anthropic API tool loop on claude-opus-5. Tools: search_corpus (ripgrep), read_doc, submit_drivers, plus server-side web_search under a triage policy: corpus-first, escalate to the public web only when the corpus can't answer, cite URLs verbatim, and report (never apply) contradictions — the merge divergence gate stays the arbiter. Runs N× per company; every tool call and skill load logged to logs/agent-trace-*.jsonl

↓ drivers.json — value, range, byte-exact citation
Citation firewall + majority vote (forecaster/extract.py)

Quotes re-found byte-exact or dropped; per-driver 2-of-3 vote; live evidence upgrades assumptions, never silently overrides reviewed anchors

↓ verified drivers only
Calibration (forecaster/engine.py)

Bias parameters fitted at runtime from 8 quarters of guide-vs-actual pairs — ADI's +$74.5M median revenue beat is computed, not asserted

↓ fitted parameters
Calculators ×12

Primary path + independent cross-check per metric; judgment drivers swept low/mid/high; final value = median of plan variants; full working saved per metric

↓ 12 values + evidence→calculation traces
Deterministic validator (forecaster/validate.py)

Completeness (all 12 cells present), unit sanity, position vs trailing 8-period history (with explicit justifications), cross-foots (EPS×shares≈NI). Accepted AND rejected values logged; a failure stops the pipeline before any workbook is touched

↓ accepted values + rejection log
Adversarial validator — a second agent (agent/validator.py)

Same corpus tools and skills as the Reader, opposite brief: try to REFUTE each computed metric — re-find every citation, check unit conventions, check against guidance and history. It may never do arithmetic or propose numbers; challenges require citations, and a blocker's quote must re-find byte-exact or the verdict is rejected back to the agent. Any blocker halts the run before the writer

↓ confirmed (or blocked with cited evidence)
Workbook writer → submission/*.xlsx

Copies official templates, fills only Summary!C7:C9 in a temp file swapped in atomically — a mid-write failure can never leave a blank yellow cell. Then a human uploads manually (the rules require it)

purple = AI reasoning (evidence in, critique out — never arithmetic) · teal = deterministic code · yellow = the deliverable

Backtests: the system scored against quarters it wasn't allowed to see

Every corpus document is date-stamped, so the corpus tools accept a date cutoff: for a holdout quarter, every document from its report date onward simply does not exist for the Reader — read_doc refuses ("this document does not exist yet for you"), search hits from hidden documents are suppressed, and the refusals are logged in the trace. A time-traveled Reader (corpus tools only — no web search, the web knows the answers) extracts the guidance that existed at the time; deterministic code anchors on the midpoint and scores it against the actual reported number from the held-out document (itself byte-verified before the run). Two honest caveats. These backtests score the raw guidance anchor — without the beat-bias calibration the live system applies: ADI's 3.4% miss IS the guidance-beat our calibration layer measures and adds (it would have moved the anchor to ~3,575). And the naive-carry-forward denominator is a weaker opponent than Wall Street; on the one holdout where we can see the street's number, consensus compiled £56.4m for Hays FY25 against an actual of £45.6m — the anchor's miss was 0.6 vs the street's 10.8. Twelve verified holdouts across the four companies ship in research/backtests/holdouts.json; judges can run any of them from the dashboard.

Why this beats "ask an AI for a number"

Run-to-run variance is engineered out, not averaged out. Downstream of the drivers everything is bit-for-bit deterministic; the two places variance genuinely lives — which facts get extracted, and judgment parameters — are handled with 3× self-consistency voting and a deterministic sweep of each judgment band with median aggregation. An ensemble of end-to-end stochastic runs converges toward what our engine computes in closed form — we just also get to show the working.

The scoring formula (min(5.0, our miss / max(WS miss, floor)), blank = 5.0) punishes blowups five times harder than boldness pays. So the system anchors to guidance, adjusts only by measured bias, deviates only with cited evidence, and takes par where it has no edge (Deere). The edges it does take — Hays' pre-announcement, ADI's quantified sandbagging, HD's acquisition wedge — are all structural facts from documents, not opinions.

What the judges can verify

  • Live observability dashboard: npm run observe → localhost:3000 — a full-bleed React Flow view of this exact pipeline with per-stage inspection, plus a live event feed: every tool call and every skill load from every agent (readers, skill-writer, adversarial validator) is an event; clicking one opens the full content re-read from the frozen corpus and rendered as markdown — the exact document slice the agent saw. A follow-cam glides the viewport to whichever stage is running. The dashboard is also a control plane: a one-button Full run drives readers → firewall → vote&merge → calibration → calculators → validator agent → writer (official checker deliberately excluded from this path; it remains the manual pre-upload gate), with a download button for the finished workbook — uploads stay manual per the rules. The Reader is user-configurable: skills checklist, tool toggles, web-search triage, extra system prompt, run count, persisted to agent/config.json.
  • The adversarial validator earned its place on day one: in its first live full run (15:20), the fresh 2-reader extraction failed to re-extract Hays' H1 finance charge, the merge fell back to the pinned £9.0m assumption band — and the validator agent blocked the writer, citing the half-year report's "The net finance charge for H1 26 was £6.7 million" byte-exact. We pinned the extracted fact at the source (with its citation), the deterministic rerun went RUN CLEAR at 1.12p, and the validator's rerun confirmed 3/3 with zero challenges. The full trail — blocker verdict, trace, fix, clean rerun — is in logs/ and the git history.
  • Dynamic skill generation: agent/skillgen.py — a skill-writer agent that studies a company's corpus and writes the Reader's company skill itself (agent/skills/<company>.md, with backup and a provenance header). A guard validates that every pinned driver key survives into the generated skill, so the pipeline contract holds even when the agent rewrites its own instructions.
  • The live loop works — with receipts: in the 13:40 live run, three Reader agents independently confirmed every reviewed Hays anchor (zero divergences through the firewall and vote), and upgraded one assumption to a fact: the actual H1 FY26 net finance charge (£6.7m) from the half-year report, collapsing the EPS uncertainty band (1.16p ± band → 1.12p, spread 0). In the HD run they went further: all three readers flagged that our $1,975M GMS inference contradicted the Q1 10-Q's stated "$1.3 billion" — the divergence policy held the reviewed value, we re-verified their quote byte-exact, and adopted it (net sales +$255M). The agents corrected their builders, with citations.
  • Traces: forecasts/traces.json — every metric's inputs (with citations), formulas, variants, cross-check deltas.
  • Tool log: logs/agent-trace-*.jsonl — every search_corpus/read_doc call the Reader made, timestamped.
  • Validation: logs/validation-*.json — 15 verdicts per run, including justified out-of-history positions.

Reproduce it

git clone https://github.com/devanshkaria88/agents-vs-wall-street && cd agents-vs-wall-street
npm install
python3 -m venv .venv && .venv/bin/pip install openpyxl anthropic
echo "ANTHROPIC_API_KEY=sk-..." > .env      # only needed for --live extraction
npm run forecast                             # engine → validate → write → check
npm run check:submission

The default run consumes the pinned, reviewed drivers (fully offline, deterministic). --live re-runs the Reader agents first and diffs their output against the pinned set — matching drivers proceed, divergences are logged and the reviewed value wins.

Honesty: what we tried, changed, and where this is weak

Changed course

  • Extraction harness, twice. Started with claude -p subprocess calls; replaced mid-build with our own API agent loop because we wanted the tool-call trace to be ours — every ripgrep query logged, not hidden inside another harness. The retired approach is still visible in git history and in forecaster/extract.py.
  • Single-run extraction → 3× voting. After challenging our own determinism claim: facts are voted 2-of-3, judgment bands are swept, medians aggregate.
  • Hays net-fees basis. We initially hedged between reported (~£903m) and continuing-ops (~£888m) after the six-country divestiture; resolved to reported group basis with the organisers and moved the anchor.

Considered and rejected

  • LoRA / fine-tuning: no training data of the right shape (12 targets, ~30 historical quarters — instant overfit), and it would swap the strong reader model for a weaker one. Wrong tool for a 6-hour, 4-company task.
  • Vector DB / RAG index: ripgrep over 1,139 markdown files is transparent and sufficient.
  • Monte Carlo / DCF: anchor + measured bias + seasonality is explainable in one sentence per metric; sophistication without evidence would be theater.

Known weaknesses

  • No channel data. Banks buy credit-card panels and dealer checks; we read what companies said. If a quarter drifted from guidance in ways only intra-quarter data shows, Wall Street beats us on that metric and the cap limits the damage to par-ish.
  • Hays EPS is a derivation, not a disclosure. The finance-charge/tax structure is solved from one half-year identity; the honest band is ~1.1–1.3p. The floor on EPS metrics is tiny, so this is our most fragile number.
  • Deere's tariff-refund allocation is opaque. Q2's PPA margin was inflated by a ~$272M recovery we cannot cleanly strip; the PPA forecast carries the widest band and deliberately hugs the year-ago.
  • Consensus may have converged on our Hays edge. The £43.5m compiled consensus predates the "top of range" statement; analysts have had five weeks to revise toward 46. Our score there degrades gracefully toward par, not badly.
  • Extraction nondeterminism is bounded, not eliminated. Voting and the firewall squeeze it; a live run can still surface a driver the pinned set lacks. Policy: divergences are logged and reviewed values win.
