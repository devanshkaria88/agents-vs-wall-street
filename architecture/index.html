Agents vs Wall Street · 16 Aug 2026

The Truth

An agent that reads 1,139 company documents, quotes its evidence byte for byte, lets deterministic code do every calculation, and refuses to be a hero anywhere it lacks receipts.

Agent name: The Truth · Team: Devansh Karia, Jack Marshall, Mani Sarkar

Build style: hybrid. Built interactively in Claude Code (claude-fable-5); the runtime is a standalone Python agent on the Anthropic API (claude-opus-5) plus deterministic Python.

Final command: npm run forecast · Repository: github.com/devanshkaria88/agents-vs-wall-street

What it does, in one paragraph

Four companies report earnings in the next four days. We forecast the twelve scored metrics by leaning on one observation: the companies have already told us most of the answers. Hays said on 10 July that FY26 operating profit lands "at the top of the £37.0-46.0m consensus range". ADI guided Q3 revenue to $3.9B, and it has beaten its own midpoint eight quarters straight, by a median of about $75M. Home Depot's quarter contains a full quarter of the GMS acquisition that the year-ago quarter lacks. The agent's job is to find those statements, quote them exactly, and hand them to code that applies the companies' own arithmetic to their own words.

The deliverable is twelve yellow spreadsheet cells. Everything below exists to put defensible numbers in them.

Three rules the whole design hangs on

  1. The AI never does arithmetic; the code never guesses. The LLM extracts facts with citations. Pure Python applies growth rates, divides profits by share counts, and blends paths. Same inputs, same twelve numbers, every run.
  2. Every corpus quote is re-verified byte-exact. A citation firewall re-finds each quoted line as an exact substring of the cited file, and a quote that does not re-find kills the driver. The agent cannot invent corpus evidence. Web citations bypass the firewall by design and are quarantined by the triage policy instead: reported, never silently applied. You can rerun the check yourself: tools/verify_citations.py re-finds all 209 shipped corpus citations, and it caught three drifted ones this afternoon, which we repaired against the documents.
  3. Never a blank cell. A missing metric scores an automatic 5.0, the worst possible. Guidance-anchored baselines went green at 11:24. Every later stage only overwrites the workbooks after validation passes, and the writer fills a temp copy and swaps it in atomically, so even a crash mid-write cannot blank a cell.

The pipeline

This is the full dataflow, driven end to end by the dashboard's one-button Full run (per company). The final command, npm run forecast, replays only the deterministic tail (engine → validate → write → check) from the pinned, reviewed drivers, which is why the final run is offline, fast, and reproducible.

Corpus

1,139 frozen markdown documents: filings, call transcripts, slides. Plus a logged, reviewed public-web consensus sweep done at 12:30.

↓ raw filings & transcripts
Reader, our own agent (agent/loop.py)

Anthropic API tool loop on claude-opus-5. Tools: search_corpus (ripgrep), read_doc, submit_drivers, and server-side web search under a triage policy: corpus first, escalate to the web only when the corpus cannot answer, cite URLs verbatim, and report contradictions instead of applying them. Runs N times per company. Every tool call and every skill load is logged to logs/agent-trace-*.jsonl.

↓ drivers.json: value, range, byte-exact citation
Citation firewall + majority vote (forecaster/extract.py)

Corpus quotes re-found byte-exact or dropped. Per-driver 2-of-3 vote. Live evidence upgrades assumptions; it never silently overrides reviewed anchors.

↓ verified drivers only
Calibration (forecaster/engine.py)

Bias parameters fitted at runtime from 8 quarters of guide-vs-actual pairs. ADI's +$74.6M median revenue beat is computed, not asserted (forecasts/calibration.json).

↓ fitted parameters
Calculators ×12

Primary path plus an independent cross-check per metric. Judgment drivers are swept low/mid/high and the final value is the median of the plan variants. The full working is saved per metric.

↓ 12 values + evidence→calculation traces
Deterministic validator (forecaster/validate.py)

Completeness (all 12 cells present), unit sanity, position against the trailing 8-period history with explicit justifications, and cross-foots (EPS × shares ≈ net income). Accepted and rejected values are both logged. A failure stops the pipeline before any workbook is touched.

↓ accepted values + rejection log
Adversarial validator, a second agent (agent/validator.py)

Same corpus tools and skills as the Reader, opposite brief: try to refute each computed metric. Re-find every citation, check unit conventions, check against guidance and history. It may never do arithmetic or propose numbers. Challenges require citations, and a blocker's quote must re-find byte-exact or the verdict is rejected back to the agent. Any blocker halts the run before the writer.

↓ confirmed, or blocked with cited evidence
Workbook writer → submission/*.xlsx

Copies the official templates and fills only Summary!C7:C9, in a temp file swapped in atomically. Then a human uploads manually, as the rules require.

purple = AI reasoning (evidence in, critique out, never arithmetic) · teal = deterministic code · yellow = the deliverable

Backtests: scored against quarters the agent was not allowed to see

Every corpus document is date-stamped, so the corpus tools accept a date cutoff. For a holdout quarter, every document from its report date onward simply does not exist for the Reader: read_doc refuses with "this document does not exist yet for you", search hits from hidden documents are suppressed, and the refusals are logged in the trace. A time-traveled Reader (corpus tools only, no web search, because the web knows the answers) extracts the guidance that existed at the time. Deterministic code anchors on the midpoint and scores it against the actual reported number from the held-out document, which is itself byte-verified before the run. We ran these live today; Hays FY25 and Deere FY2024 were launched from the dashboard's backtest panel, the rest through the same harness from the CLI, and judges can rerun any of the twelve holdouts from the panel:

Two caveats. These backtests score the raw guidance anchor, without the beat-bias calibration the live system applies: ADI's 3.4% miss is exactly the guidance-beat our calibration layer measures and adds (it would have moved the anchor to ~3,575). And the naive carry-forward denominator is a weaker opponent than Wall Street. Twelve verified holdouts across the four companies ship in research/backtests/holdouts.json, and judges can run any of them from the dashboard.

Why this beats "ask an AI for a number"

Run-to-run variance is engineered out, not averaged out. Downstream of the drivers everything is bit-for-bit deterministic. Variance genuinely lives in two places: which facts get extracted, and the judgment parameters. The first is squeezed by self-consistency voting across reader runs; the second by sweeping each judgment band low/mid/high and taking the median. An ensemble of end-to-end stochastic runs would converge toward what our engine computes in closed form. We just also get to show the working.

The scoring formula (min(5.0, our miss / max(WS miss, floor)), blank = 5.0) punishes blowups five times harder than boldness pays. So the system anchors to guidance, adjusts only by measured bias, deviates only with cited evidence, and takes par where it has no edge (Deere). The edges it does take are structural facts from documents, not opinions: Hays' pre-announcement, ADI's quantified sandbagging, HD's acquisition wedge.

In its second live full run (15:23), twenty minutes after a clean first pass, a fresh 2-reader extraction failed to re-extract Hays' H1 finance charge and the merge fell back to the pinned £9.0m assumption band. The validator agent blocked the writer, citing the half-year report's "The net finance charge for H1 26 was £6.7 million" byte-exact. We pinned the extracted fact at the source with its citation, the deterministic rerun went RUN CLEAR at 1.12p, and the validator's rerun confirmed all three metrics with zero challenges. Reproduce it

git clone https://github.com/devanshkaria88/agents-vs-wall-street && cd agents-vs-wall-street
npm install
python3 -m venv .venv && .venv/bin/pip install openpyxl anthropic
echo "ANTHROPIC_API_KEY=sk-..." > .env      # only needed for live extraction
npm run forecast                             # engine, validate, write, check
npm run check:submission

The default run consumes the pinned, reviewed drivers. It is fully offline and deterministic. Live extraction re-runs the Reader agents first and diffs their output against the pinned set: matching drivers proceed, divergences are logged, and the reviewed value wins.

Honesty: what we tried, changed, and where this is weak

Changed course

  • Extraction harness, twice. We started with claude -p subprocess calls and replaced them mid-build with our own API agent loop, because we wanted the tool-call trace to be ours: every ripgrep query logged, not hidden inside another harness. The retired approach is still visible in git history and in forecaster/extract.py.
  • Single-run extraction to voting. After challenging our own determinism claim: facts are voted across runs, judgment bands are swept, medians aggregate.
  • Hays net-fees basis. We initially hedged between reported (~£903m) and continuing-ops (~£888m) after the six-country divestiture. We resolved it with the organisers to the reported group basis and moved the anchor.
  • The backtest harness had a units bug we caught the same hour. HD guides growth rates, not dollars, and the first HD holdout run anchored on 3.5 as if it were millions, against an actual of 41,765. We added an explicit anchor mode so code applies growth guidance to the year-ago base. The broken run and the fix are both in the history.

Considered and rejected

  • LoRA / fine-tuning. No training data of the right shape (12 targets, ~30 historical quarters is an instant overfit), and it would swap the strong reader model for a weaker one. Wrong tool for a one-day, 4-company task.
  • Vector DB / RAG index. ripgrep over 1,139 markdown files is transparent and sufficient.
  • Monte Carlo / DCF. Anchor plus measured bias plus seasonality is explainable in one sentence per metric. Sophistication without evidence would be theater.

Known weaknesses

  • No channel data. Banks buy credit-card panels and dealer checks; we read what companies said. If a quarter drifted from guidance in ways only intra-quarter data shows, Wall Street beats us on that metric and the cap limits the damage to roughly par.
  • Hays EPS is a derivation, not a disclosure. The finance-charge and tax structure is solved from one half-year identity. The honest band is about 1.1p to 1.3p, and the floor on EPS metrics is tiny, so this is our most fragile number.
  • Deere's tariff-refund allocation is fuzzy. Q2's PPA margin was inflated by the segment's share of a ~$272M refund recovery. On the Q2 call management put about 20% of it in large ag, but only approximately, so we cannot precisely strip it. The PPA forecast carries the widest band and deliberately hugs the year-ago.
  • Consensus may have converged on our Hays edge. The £43.5m compiled consensus predates the "top of range" statement, and analysts have had five weeks to revise toward 46. Our score there degrades toward par rather than blowing up.
  • Extraction nondeterminism is bounded, not eliminated. Voting and the firewall squeeze it, and the adversarial validator now catches what slips through: when a 2-reader run regressed the finance charge today, the validator blocked the workbooks before a stale assumption could ship. Divergences are logged and reviewed values win.
